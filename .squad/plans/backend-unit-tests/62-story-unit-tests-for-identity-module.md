## Test conventions (apply to every slice)

- Namespaces mirror folders: `Crm.Modules.Identity.Tests.Domain`, `…Tests.Application.Commands.SignIn`, … Class name = production type + `Tests`. Use full `using` aliases where a name clashes (e.g. `Crm.Modules.Identity.Domain.EmailAddress` vs FluentValidation's `EmailAddress()` extension, or the Identity `User` type vs a test namespace segment).
- Domain errors: `Assert.Throws<DomainException>(…).Error.Code`. Result failures: `result.IsFailure`, `result.Error.Code` **and** `result.Error.Type` through a copied `Expect.Failure(result, code, ErrorType.X)`. Codes asserted as string literals (`IdentityErrors` is internal).
- Handlers get **substituted** `IRepository<,>` (`User`/`UserId`, `RefreshTokenFamily`/`RefreshTokenFamilyId`, `PortalAccount`/`PortalAccountId`, `PortalSession`/`PortalSessionId`), `IIdentityUnitOfWork`, `IPasswordHasher`, `IRefreshTokenGenerator`, `IAccessTokenIssuer`, `ICurrentUserService`, `IOrganisationModuleApi`, `ICustomersModuleApi`, `IDateTime` (`Clock.Fixed()`), `SessionSettings` (a real record: refresh lifetime 14 days, 5 attempts, 15 minutes), `RecordingLogger<T>`. `Task<T?>` repository returns use `Returns(Task.FromResult<T?>(x))`; `SaveChangesAsync` asserted with `Received(1)` on commit paths and `DidNotReceive()` on every failure path; `ListAsync`/`FirstOrDefaultAsync`/`CountAsync` stubs go through `Arg.Any<Specification<T>>()` helpers (copy of `Stubs`), plus capture of the specification type (`Arg.Is<Specification<User>>(s => s is UserByEmailSpecification)`).
- Hashing is stubbed (`hasher.Hash("x").Returns("hash-x")`, `hasher.Verify("hash-x","x").Returns(true)`); **real PBKDF2 is touched only in `AspNetPasswordHasherTests` and the seeder test** (R5).
- Validators: `validator.Validate(command)`; assert `result.IsValid` and the failing `PropertyName`s through a copied `Expect.Valid/Invalid`; validators with `ILocalizationService` get `FakeLocalization.Keys()` for structure and `FakeLocalization.Resources()` (real `.resx`) for the message-text checks.
- Cancellation, `[Theory]` over cases instead of loops, one InMemory database name per test, no static mutable state in `Support/`.
- A culture-changing test class uses `UiCulture` (copy) and a `[Collection]` so cultures cannot leak into parallel classes.

## Edge Cases & Failure Modes

- **Failed sign-in is a committed fact.** `SignIn`, `RefreshSession`, `PortalSignIn`, `RefreshPortalSession` return a **successful** `Result<SignInOutcome>` with `Succeeded = false` so the counter or the revocation commits. Each test asserts both `result.IsSuccess` and `Outcome.FailureCode`, and whether `SaveChanges` was called (wrong password: yes; unknown / inactive / locked / malformed: no; reuse: yes; expired / revoked: no; portal-access-revoked on refresh: yes, on sign-in: no).
- **One generic failure, no oracle.** Every refusal path of the two sign-ins yields the identical outcome and calls `VerifyAgainstDummy` when no real verification ran; asserted by call patterns (timing cannot be asserted). Logs carry the reason and ids only; a `RecordingLogger` test asserts no entry contains the email or password text.
- **Result vs exception.** Expected business failures are Results (`NotFound`, `Forbidden`, `Conflict`, `Domain`, `Validation`, `Unauthorized`); aggregate invariants (`UserAlreadyInactive`, `UserAlreadyActive`, `EmailInvalid`, `LocaleUnsupported`, `DisplayNameRequired`) are `DomainException`s that propagate out of handlers (the host turns them into 422). Each test asserts the right one of the two.
- **Handlers do not re-validate.** Input the validator would have stopped (`a@b`, `fr`, blank name) reaching a handler surfaces as a `DomainException`; pinned by name.
- **Tenant guard.** Admin handlers compare `user.TenantId` to `currentUser.Scope.Tenant`; out-of-scope = `Forbidden` `Organisation.OutOfScope`, evaluated **before** the self-deactivation check and before `SetOriginalRowVersion`.
- **Concurrency.** Handlers call `SetOriginalRowVersion` with the client's bytes before saving; the conflict itself is UT-01's and not reproducible on InMemory. Assert the call and its order only.
- **Internal types.** `IdentityErrors`, `AccessTokenSubjectFactory`, `PortalAccessTokenSubjectFactory`, `PortalMeMapper`, `JwtSettings.Validate` are `internal` with no `InternalsVisibleTo`; they are covered through `SignIn` / `RefreshSession`, `PortalSignIn` / `RefreshPortalSession`, `GetPortalMe` / `UpdatePortalProfile` and `IdentityModule.AddServices`. Adding `InternalsVisibleTo` is a production change and not allowed here.
- **Floating clock.** Never `UtcNow`; boundaries (`until == now`, `expires == now`, `ExpiresAtUtc <= now`) use fixed offsets of one tick.
- **Parallelism.** One InMemory database name per test; PBKDF2 only where listed; no static mutable state.
